# AI architecture (planned)

The first server-side AI seam is implemented at `POST /api/ai/slo-review`. It is disabled until both `OPENAI_API_KEY` and `OPENAI_KNOWLEDGE_VECTOR_STORE_ID` are set on the server. The `/api/ai/status` route provides a clear development-state message, while `src/lib/ai/retrieveKnowledge.ts` exposes a retrieval boundary for structured services. It queries only the project knowledge vector store, never local faculty-uploaded files. `src/lib/ai/client.ts` uses Responses API File Search with `store: false` and strict JSON-schema output, validated again by application code. API keys never enter client bundles.

`.env.example` contains variable names only. The intended knowledge collection is Learning That Matters, Transparent Assignment Design, Reviewing & Creating SLOs, Reframing How We Teach, Summary of Teaching with AI, and other approved NKU resources. No knowledge file, vector-store ID, or credential is included in this repository.

The implemented SLO Review service uses Responses API File Search, strict JSON-schema output, and a second application-level validation. Its approved knowledge categories are declared in `src/lib/ai/knowledgeSources.ts`: Summary of Teaching with AI; Learning That Matters chapters 3–9 topics (backward design/UDL, SLOs/portable outcomes, DIQ, connected assessment, projects/TiLT, active learning, and student support); Transparent Assignment Design; Reviewing & Creating SLOs with AI; Reframing How We Teach; and Using AI to Transform Assignments. Repository code, specifications, and software-development material are deliberately not pedagogical sources. Updating vector-store files does not require app-code changes.

AI controls are centralized in `src/lib/ai/featureConfig.ts`, `pricing.ts`, `limits.ts`, and `usageLedger.ts`. Requests are disabled unless `AI_ENABLED=true`, the feature and its model tier are enabled, and server credentials/vector-store configuration are present. The request path estimates and validates cost before calling OpenAI, then records returned token usage without retaining prompts or raw course material. See `docs/ai-cost-controls.md` for administrator configuration and prototype limitations.

For an SLO review, the browser sends only the selected outcome plus title, discipline, level, modality, description, goals, and up to three relevant course-material excerpts. It never sends the whole CourseRecord. The response stores the original outcome, structured review, visible source metadata, assumptions, faculty decision, final wording, and timestamps—not prompts, tokens, debug output, or an unbounded raw response. Deterministic relationship checks and Activity Builder ranking remain outside the AI layer.
